# User Endgame Roadmap

Whoever knows the user best wins. Building for everyone = building for no one (confused signups, muddled free model, chaotic onboarding, confusing pricing, churn).

Users ≠ buyers. In B2B, build for the people who use it daily; they'll champion it to the buyer.

## Phase 1 — Identify ONE ideal user
An ideal user: loves the product *as it is now*, retains, gets outsized results, and is strategic (others look up to them).
1. List 5–10 candidates (job titles / profiles).
2. Score each High/Med/Low on **Motivation** (something pushing them), **Ability** (easy for them to use it), **Prompts** (problem stays top of mind). Tie-breakers: market size, free→paid rate, retention.
3. The top scorer isn't automatically right — skip a saturated segment if another plays to the product's strengths (e.g. a security tool picking "developer forced to handle security" over "security engineer").
4. Commit to one. Decide with 40–70% of the information. Check with head (what the data says), heart (what feels right), gut (what you have the courage to commit to).
Switch only after sustained bad conversion, referrals and retention.

## Phase 2 — Clarify the endgame
1. List outcomes users get when successful: what do they **see, feel, hear**?
2. Pick the top 3, ideally one each: **fix** (immediate pain), **prevent** (fear/risk), **improve** (long-term gain).
3. Write a **User Endgame Statement**: one line, inspiring, simple, achievable, deliverable by the product, makes clear what it's not. (Canva: design anything, publish anywhere. Zapier: automate your busy work.)

## Phase 3 — Map the roadmap (5 stages × 2 milestones)
List 5–8 challenges at each milestone; ask what users see/feel/hear.
1. **Search** — Problem aware → Active research. (Info overload, cost fears, fear of change, jargon, complacency.) Job: educate on the root problem.
2. **Select** — Visit → Sign up. (Unclear value, too many CTAs, slow site, no trust signals, long forms, card required, confusing limits.) Use session recordings.
3. **Setup** — Profile (2–5 questions after signup to personalize) → Onboarding. 40–60% are lost here without intentional design.
4. **Showcase** — **First Strike** (first experience of core value; enough to come back, not the whole product) → **Key Usage Indicator / KUI** (core value repeated, often 3+ times; e.g. a team's 2,000th message). Blockers fall into product, knowledge or skill gaps.
5. **Scale** — Upgrade (what are they upgrading *in their life*? e.g. remove "powered by" branding to look professional) → Advance (grow into more usage; co-develop the next level with customers).

## Output: User Endgame Canvas
Ideal user + why · top 3 outcomes · endgame statement · stage-by-stage challenges · named First Strike and KUI · top 3 challenges to attack first.
Then validate by talking to real users (`plg-jtbd-outcomes`). Revisit as the market changes.

Source: *The Product-Led Playbook* (Wes Bush), ch. 2. Unofficial summary.
